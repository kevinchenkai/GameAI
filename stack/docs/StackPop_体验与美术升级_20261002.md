## 2. 代码检查结果与修复

### 2.1 动画的尺寸语义错误

原胜利动画、星星和消除粒子先 `setDisplaySize()`，随后又 `setScale(1)`。Phaser 的显示尺寸实际保存在 scaleX/Y 中；后者会恢复原始纹理尺寸，不是此前设定的 CSS/DPR 尺寸。星星和粒子会意外放大；跳过动画也会复现。

`GameScene.ts` 现在捕获原 scaleX/Y，以其为基准做动画和恢复。移动端 DPR2 下实测通关面板 310.8×310 CSS px，三颗星星均为 38×38 CSS px；点击跳过后仍为 38px。

### 2.2 killAll 不等于完成异步交互

销毁 tween 时，不保证它的 onComplete 被调用。原取牌流程以 onComplete resolve Promise：快速重开/退出可能留下永远 pending 的交互，随后阻塞 InputQueue；Worker 旧结果还可能覆盖新局。

新增 `systems/AnimationTasks.ts`，场景所有被 await 的 tween/timer 统一登记，正常结束 resolve(true)，取消 resolve(false)。重绘/重开/shutdown 时先取消异步任务，再 kill tween 和销毁对象。

同时增加每局 `runVersion`，每次 await 后验证仍属于本局；shuffle 使用 AbortController，重开和 shutdown 主动 terminate Worker，取消不走安全回退、不计工具消耗。Worker 创建或 postMessage 异常仍走既有确定性安全回退。

InputQueue 增加 dispose 和异常收口：shutdown 拒绝新输入，失败时清空旧排队，后续输入仍可继续使用；上限仍是“当前执行 + 最多两个等待”。

### 2.3 规则状态与表现阶段分离

原流程 core 完成 pick 后立即画最终 Tray，再播放飞牌：同一张牌飞行时已经出现在槽位中；三消可能在第三张抵达前消失。

现在规则仍由 `core/rules/` 一次性算完，不在渲染层重写规则。只把 Tray 显示分为三阶段：

1. 飞行期间显示 before.tray。
2. 到达后按规则返回的 insertedTrayIndex 显示插入态，按 shiftedTileIds 平移受影响图案。
3. 消除淡出完成后显示 nextState.tray。

这里重建的是视觉插入态，不自行判断匹配或胜负。真实浏览器探针确认：三消飞行期显示两张，到达后才显示三张，再消除。

### 2.4 动态效果与交互细节

- `prefers-reduced-motion` 不再仅影响胜利动画：点击缩放、飞牌、粒子、槽位位移、摇晃和预警呼吸也遵守。压力文字和边框不消失。
- Tray 6/7 只脉动底板 alpha，不缩放整个容器，避免图案/命中位置漂移。实测 root.scaleX 始终为 1。
- 重来确认期间拒绝棋盘输入；设置页的“重新开始”也增加确认，避免从另一入口丢失本局。
- 首页、设置页、关卡选择复用既有 RoundedButton / 圆角材质；不另建按钮样式真源。
- 关卡选择使用既有 fx-star 图像，而非系统字体星形；取消只缩放卡片底色、文字却不动的 hover。
- 玩法页示例图案与棋盘/Tray 使用相同比例，覆盖牌只压暗 frame，不再压图案饱和度。

## 3. 美术交付

### 3.1 风格和产出

先生成粉色 paw 作为 Master Reference，其他图案以它作为风格参考，逐张生成。统一圆润体积、温暖深色轮廓、宽而克制的高光；减少内部细纹，优先保证小尺寸轮廓区别。

本轮生成 11 张：八张 Tile、两张背景、一张蓝色设置按钮。另机械裁切两张既有胜负底板的透明外留边，不重画已批准材质。原留边使布局的 16px padding 对准透明画布而非可见边框，按钮视觉上贴到框外；裁切后恢复实际内边距。

八张 Tile 保持原色彩身份：粉 paw、绿 grass、蓝 watering、金 bell、橙 fish、紫 yarn、米白 bone、深棕 flowerpot。未改 Tile 类型或关卡分布。背景中部保持低干扰，首页小猫与花园主要位于底部，游戏背景不加角色。

### 3.2 实际像素门槛

所有 Tile 是 256×256 真透明 WebP，无奶油框、无烘焙棋盘格。最终可见 alpha 包围盒最大边均为 174px（67.97%），位于 206px 安全区内。加工先裁切原图、缩小，再按缩小后实际可见边界归一化；避免极淡边缘在缩小后消失、导致真正主体不足 62%。

| 图案 | WebP 字节 | alpha 加权 mean L（Rec.709，0–255） |
| --- | ---: | ---: |
| paw | 12,612 | 136.79 |
| grass | 10,682 | 155.68 |
| watering | 8,964 | 152.02 |
| bell | 10,056 | 183.66 |
| fish | 9,160 | 135.88 |
| yarn | 10,290 | 137.47 |
| bone | 7,938 | 210.91 |
| flowerpot | 9,720 | 101.96 |

bell / flowerpot 亮度差 81.70，超过历史门槛 38；flowerpot ≤140。bone / fish 差 75.03。这里的 mean L 是上述定义，不声称和历史文档未明确公式的 L 完全同口径。

八图合计 79,422 字节；home / game 背景均为 1125×2436，分别 35,288 / 17,550 字节。13 个交付文件合计 174,480 字节；22 个首屏纹理合计 227,754 字节（222.42KiB），原版对应 176,748 字节，增加 49.81KiB。首屏纹理新增 <300KiB 回归门槛，未把 BGM 塞进 preload。

所有换图路径使用 `_v2.webp`，Asset Manifest key 不变；不覆盖旧 URL，遵守静态图 30 天缓存纪律。原版文件保留，便于回滚。

## 5. 保留问题与下一步

1. 未部署，不声称 Safari / iPhone 真机已经验收；需人类实际检查触感、图案辨识和浏览器安全区。
2. 全量 npm audit 仍报告 7 个开发工具链漏洞（3 moderate / 3 high / 1 critical）；生产依赖 audit 为 0。主要涉及既有 Vite/Vitest 与 lint 传递依赖。本轮不把美术与交互升级扩大成多个 major 的构建工具迁移；dev server 继续仅绑定 127.0.0.1，不启用 Vitest UI 对外服务。应另开依赖升级验收。
3. Phaser chunk 仍约 1.48MB 原始 / 338KB gzip。已有独立 chunk；没有做无官方支持的裁剪构建，不以少量交互改动宣称包体显著下降。
4. GameScene 仍偏长，本轮抽出了异步生命周期管理，没有重构全部渲染和游戏状态流，以免扩大回归面。
5. 工作区同时出现根站点 index.html / images / scripts 的其他改动，本轮未改动、未整理进 StackPop 的交付范围。
