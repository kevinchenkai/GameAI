## R4-0 ★ 前置｜统一的「减少动态效果」开关

### 这不是美化，是先补地基

我扫了全部 tween 调用点：`src/` 共 **13 处 `tweens.add`**，
其中 1 处是 `BackgroundMusicScene` 的音量淡入淡出（属音频，不在本议题内），
**其余 12 处视觉动画里只有 1 处**尊重系统的减少动态效果设置：

```
GameScene.ts:442   animateWin 的三条件之一   ✅ 唯一一处
GameScene.ts:552 / 559 / 569 / 629 / 687 / 690 / 718 / 734 / 751 / 762   ❌
TrayRenderer.ts:148 / 161（成对闪光、危险呼吸）                          ❌
```

也就是说：前庭敏感玩家开了系统「减少动态效果」后，
**当前仍会看到危险呼吸、成对闪光、取牌缩放等全部动效**。

R4 后续每一项都要新增动画。**先不补这个开关，就是在同一个坑上再挖几次。**

### 要求

1. 新增 `game/ui/motionPreference.ts`：

```ts
/** 系统「减少动态效果」是否开启。每次读取，不缓存——用户可能中途改设置 */
export function prefersReducedMotion(): boolean;
/** 按偏好折算时长：开启时返回 0（或 ≤80ms），关闭时原样返回 */
export function motionDuration(ms: number): number;
```

2. 全部 12 处 tween 走这个 helper。**装饰性动画**（呼吸、闪光、庆祝粒子、
   超调缓动）在开启时**完全跳过**；**功能性动画**（取牌位移、Tray 移位——
   玩家需要靠它理解「牌去哪了」）保留但压到 ≤80ms。
3. `animateWin` 现有的内联判断改用同一 helper，避免两套逻辑。

### 验收门槛

- [ ] `grep -rn "tweens.add" src/` 的 12 处**视觉**动画每一处都能追溯到
      `prefersReducedMotion` 或 `motionDuration`（`BackgroundMusicScene` 的音量淡入除外）
- [ ] 新增测试断言：装饰性 / 功能性两类各至少一例，开启偏好后时长分别为 `0` 与 `≤80`
- [ ] **反向验证**：把某处 helper 换回硬编码时长，测试变红

> 分类有判断空间。**拿不准的归到「功能性」**——保守侧的代价只是动画短一点，
> 激进侧的代价是玩家看不懂棋盘发生了什么。

## R4-1 P1｜HUD 补进度条（当前完全缺失进度感）

### 现状

HUD 是「第4关 / 步数 5 / 剩余 36 张 / ⚙」，信息正确但偏报表。
**玩家无法一眼判断「还剩多久通关」** —— 36 张是多是少，没有参照。

### 要求

1. HUD 底边贴一条 2~3px 细横条，按 `(总数 - 剩余) / 总数` 填充
2. 填充值变化走补间（`motionDuration(200)`），不要跳变
3. 颜色用暖色系（与 `GAME_UI.surfaceCream` 面板协调），**不要**用红/绿——
   红绿会与「危险」语义混淆，也对色盲玩家不友好
4. 总数取关卡初始牌数，从 `state` 推导，**不要**在 `core/` 加字段

### 验收门槛

- [ ] 进度条高度 ≤3px（`px()` 换算后），不增加 HUD 面板总高
- [ ] L1 开局填充 0%，通关瞬间 100%，中途单调不减
- [ ] 灰度截图下进度条与底色**仍可区分**（沿用 R2 的灰度可辨纪律）
- [ ] 减少动态效果开启时，填充**瞬时**到位而非补间

## R4-2 P1｜背景分层视差

R3 §4 已论证过：**不重画素材**，用现有 `game_bg` 加分层即可。

### 要求

1. 棋盘区上方留白放 1~2 朵极淡的云，随棋盘居中位置极缓慢移动
2. 猫咪水印上移到棋盘区与 HUD 之间的留白中心

### 验收门槛（**这几条是硬约束，超出即打回**）

- [ ] 任何背景元素 `alpha ≤ 0.3`
- [ ] 背景元素**不得进入棋盘卡片正后方**——需给出一张标注了棋盘外接矩形的截图自证
- [ ] 改动前后各测一次 covered/active 亮度差：**仍 ≥25 点**
      （R2-A 实测 175.1 vs 202.1 = 27 点；只采样奶油色边框，不要采整条 32px）
- [ ] 视差位移幅度 ≤ 屏宽 2%，周期 ≥8s——要「几乎察觉不到」，不是「会动的壁纸」
- [ ] 减少动态效果开启时，云**静止**（仍显示，不移动）

> 若做完仍嫌单调，**再**讨论开 MA4 重画背景。不要在本轮直接跳到重画。

## R4-3 P2｜顶牌呼吸 + 落位缓冲

### 要求

1. 每列可点顶牌 `scale 1.0 ↔ 1.015`，周期 2s，**相位随列错开**
   （同相位会变成整排一起跳，很廉价）
2. 牌进 Tray 的缓动由 `Quad.easeOut` 改 `Back.easeOut`，加轻微超调

### 验收门槛

- [ ] 呼吸幅度 ≤1.5%，肉眼「感觉得到但说不清」
- [ ] 呼吸**不影响命中区**——命中区来自 `calculateBottomAlignedBoardPlacements` 的
      纯函数返回值，不得因 scale 变化而漂移。这条务必实测点击边缘
- [ ] 超调幅度不使牌越出 Tray 槽位边界
- [ ] 两者在减少动态效果开启时均**完全跳过**

> ⚠️ 第 2 条命中区是本项唯一的真风险。R1 好不容易做到「渲染与测试共用同一套坐标」，
> 别让呼吸动画把它破坏掉。

## R4-4 P3｜数字跳动反馈

「剩余」数字变化时 scale 1.2 → 1.0，120ms。
给消除一个额外正反馈落点。成本极低，做不做都行。

R3 §5 还提过「步数降级为小字号，把权重让给剩余」——
**这条我建议不做**：步数与三星评级直接相关，缩小会削弱玩家对评级的感知。
如果 Kevin 认为休闲定位下步数确实不重要，再单独讨论。

## 建议顺序与取舍

| # | 项 | 优先级 | 成本 | 风险 |
|---|---|---|---|---|
| **R4-0** | **减少动态效果开关** | **前置** | 中 | 低 —— 但**不做会污染后面全部** |
| R4-1 | HUD 进度条 | P1 | 低 | 低 |
| R4-2 | 背景分层视差 | P1 | 中 | **中**——可能吃掉对比度，门槛已写死 |
| R4-3 | 顶牌呼吸 + 落位缓冲 | P2 | 低 | 中——命中区漂移 |
| R4-4 | 数字跳动 | P3 | 极低 | 无 |

**建议本轮只做 R4-0 + R4-1 + R4-2**，验收通过后再评估 R4-3。
R4-3 的命中区风险需要真机点测，与 R4-2 混在一轮里不好归因。
