# StackPop UI R3｜玩法页与结果页执行与验收记录

日期：2026-08-24

状态：实现完成，待 iPhone 真机与 Claude 独立验收

依据：用户 iPhone 通关截图、`UI_R3_美化建议_Claude_20260824.md`

## 1. 本轮目标

本轮只打磨玩法说明与结果反馈，不改关卡、规则、棋盘布局、Tile 尺寸、
纵向重叠率、Tray 契约或命中坐标。

真机截图中的主要问题是：

1. 通关弹窗尺寸偏大，统计信息挤成一行，中段却有大量无效空白；
2. 三个结果按钮连成“表格栏”，没有主次和破坏性语义；
3. 玩法说明以长段文字为主，第一次打开时不能“看图就懂”；
4. 玩法页返回按钮与翻页按钮的触控高度不足 44px；
5. 胜利弹窗直接出现，缺少完成整局后的情绪反馈。

## 2. 玩法说明页

四页分别新增一个 82px 高的即时示意区：

| 页 | 图示 |
|---|---|
| 基本玩法 | 三张叠牌 + “点最下方露出的卡牌” |

继续复用 `resolveToolButtonStyle()`，不增加第二套样式真源。

## 3. 通关页

- 弹窗最大宽度 320px、高度 310px，不再占据近半屏的大方框；
- 三颗星、标题、统计、鼓励语和操作区形成五级垂直层级；
- 步数 / 撤回 / 打乱拆成三张 44px 统计卡；
- 下一关为黄色主按钮，再玩一次为浅底次按钮，选择关卡为弱化按钮；
- 三按钮间保留 8px 间距，全部圆角、描边、阴影和按压态与底部工具栏一致；
- 最后一组三消后继续保留既有 300ms 停顿，再播放面板弹入、星星依次弹入和
  现有 sparkle 粒子；总时长小于 1.2s；
- 动画期间第一次点击直接跳到终态；系统启用 `prefers-reduced-motion: reduce`
  时不播放庆祝动画。

## 4. 失败页与“打乱”决策

没有采纳“失败弹窗开启打乱”的建议。原因不是视觉取舍，而是规则约束：

- 失败条件是 Tray 已满 7 格；
- 打乱只重排剩余列，明确不改变 Tray；
- 因此失败后即使重排牌堆，也没有空槽完成下一次取牌，无法恢复为合法局面。

若强行启用，要么 Worker 返回不可救状态，要么必须清空 Tray，后者会改变既定规则。
本轮删除了这个不可执行的灰色按钮：有撤回记录时展示“撤回一步 / 重新开始”两条
真实路径；无撤回记录时只展示一个“重新开始”主按钮。提示文案同步改为
“撤回一步，回到槽位未满时”。

失败弹窗独立收短为 250px，避免复用通关高度产生大段空白。

重来二次确认也移除了旧的直角矩形按钮，改为圆角奶油面板：取消为次级，确认
重来为弱化的破坏性操作。根据 Claude `ff5d35f` Code Review，随后抽取公共
`ui/RoundedButton.ts`；底部工具栏、胜负弹窗、重来确认和玩法页翻页按钮现在都
调用 `createRoundedButton()`，圆角、描边、阴影、图标、角标、disabled、hover
和 pressed 只有一份渲染实现。

## 5. 视觉参数单一真源

本轮新增参数全部位于 `GAME_UI`：玩法面板圆角/透明度、示意区高度、44px 触控
下限、结果面板尺寸、统计卡、按钮、遮罩以及胜利动画时序。旧的
`PROTOTYPE_UI.result*` 参数已删除，避免两套数值并存。

新增 `uiR3.test.ts` 8 项契约，覆盖：

1. 玩法页操作命中区 ≥44px；
2. 四类图示确实引用真实游戏纹理；
3. 玩法页复用统一按钮样式且不缩放交互对象；
4. 通关/失败面板尺寸、统计卡和按钮间距；
5. 失败页不存在不可执行的“打乱”按钮；
6. 胜利动画可跳过、≤1.2s 且尊重减少动态效果。
7. 重来确认复用结果按钮材质，不保留旧的第三套矩形按钮；
8. 工具栏、结果弹窗与玩法页共同引用 `RoundedButton` 唯一实现。

另外在 `shuffle.test.ts` 新增核心回归：构造 Tray 7/7 且每种 Tile 总数仍满足
三消的失败局面，`findSolvableShuffle(..., maxAttempts=0)` 必须抛出
`Current tray cannot be rescued by any next pick`。这证明失败后只重排列、保持
Tray 不变的“打乱”无法成为恢复路径；不能用 `remainingShuffles > 0` 取代 UI 的
禁用判定，否则会制造一个可点击但必然失败的 Worker 操作。
