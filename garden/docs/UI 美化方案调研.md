## 0. 一句话结论

**当前 UI 不难看，但"没做完"** —— 缺的不是美术资源，是**三样几乎零成本的东西**：

1. **反馈特效全是空的**（`cascadeStart` / `levelWin` / `levelLose` 在 EventPlayer 里是空 case）
2. **视觉层级只有一档**（全项目零渐变、零阴影，面板就是纯色圆角矩形）
3. **特殊棋子叠加层风格断裂**（水果是柔和 3D，标记是扁平剪贴画）

前两条**纯代码，不需要 Codex**。第三条需要重出 3 张图。

## 1. 现状盘点（实测，非印象）

### 1.1 UI 是怎么画出来的

| 层 | 实现 | 素材依赖 |
| --- | --- | --- |
| 棋子 / 冰 / 院门 / 旺财 | PNG 贴图 | ✅ Codex 已交付 |
| 面板 / 按钮 / HUD / 进度格 | **Phaser Graphics 手绘** | ❌ 零贴图 |

> 📌 UI 全部 Graphics 绘制是**刻意的**（要按 DPR 缩放、跟随主题色），
> 也正因如此，**改视觉基本等于改代码**，不必等美术。

### 1.2 实测到的三个具体问题

**① 反馈特效是空的**

`EventPlayer` 里这三个事件是**空 case**：

```ts
case 'cascadeStart':
case 'levelWin':
case 'levelLose':
  // M5 接特效与 HUD；M4 只保证时间轴与位移正确
```

后果：
- **5 连锁和 3 消看起来一模一样** —— 玩家感知不到"我打出了大连击"
- **过关没有任何庆祝** —— 直接弹结算框
- 消除只有"缩小淡出"，没有爆开、没有闪光

而 `config/tuning.ts` 里的 `FX_QUALITY`（粒子数、震屏开关）与 `FX_SAMPLING`
（帧率采样降级）**全项目零引用** —— 配置写好了，没人消费。

**② 视觉层级只有一档**

全项目 **零渐变、零阴影**（`grep Gradient|setShadow|dropShadow` 无命中）。
面板是纯色圆角矩形 + 描边，按钮同理。缺的是：
- 卡片没有投影 → 浮不起来，和背景一个平面
- 按钮没有按下态 → 点了没有"陷下去"的反馈
- 背景是**单一纯色** `#FFF6E5`，没有任何层次

**③ 特殊棋子叠加层风格断裂**（用户已指出"很丑"）

我把 3 种标记贴到六色棋子上渲染出来看了：

- **横/竖火箭**：扁平的**双向箭头**，硬边、纯色描边 —— 剪贴画风
- **炸弹**：一个**细金圈** + 小星星，读起来像装饰边框，不像"会爆炸的东西"

而水果是**柔和 3D、有高光有环境光**。两者放一起明显不是一套。

> ⚠️ 但它们**可读性是达标的**（灰度差最差 43.7 ≥ 20 判据）。
> 这是纯观感问题，不是功能问题。

### 1.3 顺带查到的两个代码缺陷

| 缺陷 | 位置 | 后果 |
| --- | --- | --- |
| **BoardView 零 `px()` 换算** | `BoardView.ts:142,310` | 格子圆角、间隙、**选中框 4px 描边**在 DPR=2 手机上只有一半视觉粗细 |
| **16 处硬编码颜色** | UI 各处 | `ENV_PALETTE` 里已有同款色值，但代码里又写了一遍 `0x8a6a4a` 等。**换主题要在 6 个文件里翻** |

第二条直接卡住任何"整体调色"的想法 —— 应当在美化前先修。

## 2. 可以做什么（按性价比排序）

### 🥇 A 类：纯代码，不需要 Codex，收益最大

| # | 事项 | 效果 | 成本 |
| --- | --- | --- | ---: |
| **A1** | **消除粒子 + 连锁反馈** | 3 消有小爆开；5 连锁有渐强的光效与音调 —— **"爽"的主要来源** | 中 |
| **A2** | **过关庆祝** | 星星逐颗跳出、旺财跳跃、轻微礼花 | 中 |
| **A3** | **面板投影 + 按钮按下态** | 卡片浮起来、点击有回弹 —— 廉价但立竿见影 | 小 |
| **A4** | **背景层次** | 单色 → 柔和垂直渐变 + 极淡的装饰纹理（Graphics 画，零素材） | 小 |
| **A5** | **修 `px()` 缺失 + 收敛硬编码色** | 选中框恢复应有粗细；为后续换肤铺路 | 小 |
| **A6** | **HUD 目标完成的瞬间反馈** | 目标达成时图标弹一下 + ✓ 划入，而不是静态出现 | 小 |

> **A1 + A2 是"游戏感"的核心。** 三消好不好玩，很大程度取决于消除那一下的反馈。
> 目前这一下是"缩小淡出"，属于**功能正确但毫无爽感**。

### 🥈 B 类：需要 Codex 出图

| # | 事项 | 张数 | 说明 |
| --- | --- | ---: | --- |
| **B1** | **特殊棋子叠加层重做** | 3 | 用户已点名。要求：与水果同风格（柔和 3D、暖色、有厚度），**不是扁平箭头** |
| **B2** | 关卡页背景 | 1 | 目前是纯色。可出一张极淡的花园远景（**必须极淡**，不能抢棋子） |
| **B3** | 粒子贴图 | 1~2 | A1 若要更精致，需要小星/花瓣贴图；不出也能用 Graphics 圆点 |

> ⚠️ **B2 有风险**：背景一旦有细节，就会和棋子抢注意力，
> 对 50+ 用户尤其危险。**建议先用 A4 的纯代码渐变**，真人测试后再决定要不要真背景图。

### 🥉 C 类：暂不建议

| 事项 | 为什么不做 |
| --- | --- |
| 换整套 UI 贴图（九宫格面板等） | 上次刚删掉 660KB 从没被画过的 UI 贴图。Graphics 方案在 DPR 缩放与换色上更灵活，**换回贴图是倒退** |
| 旺财 thinking/hint 专属动作 | 属"陪伴感"不属"美观"，且 Puppet 5 层表达力有限。等 M8 反馈 |
| 骨骼动画 / Spine | Stage 0 体量用不上，引入成本远大于收益 |

## 3. 对 Codex 的工作量评估

**只有 B 类需要 Codex，合计 3~6 张图。**

### 必做：B1 叠加层重做（3 张）

这是唯一**用户已明确点名**的美术项。要点：

| 项 | 要求 |
| --- | --- |
| 风格 | 与 `piece-*.png` 同一套：柔和 3D、暖色调、有高光与厚度 |
| 火箭 | **不要双向箭头**。建议：有体积的小火箭/推进尾焰，沿轴向 |
| 炸弹 | **不要细圈**。建议：有重量感的球体 + 引线，或明确的爆裂纹理 |
| 尺寸 | 256×256 真 RGBA，与现有一致 |
| 硬判据 | 六色棋子上灰度差 ≥ 20（沿用 LEGIBILITY-SPEC §5.2） |
| 交付 | **未压缩原图**，压缩由代码侧统一做 |

⚠️ **工单必须写清"叠加层是标记，不是遮挡"** —— 上次就是把冰的遮挡约束
错套到标记层，导致 Codex 每个数字都达标但浅色棋子上完全看不见
（已记入 LEGIBILITY-SPEC §5.2，这次要引用那一节）。

### 可选：B3 粒子贴图（1~2 张）

小星星 / 花瓣，128×128 即可。**不出也能做** —— Graphics 画圆点足够，
只是精致度差一档。建议**先用 Graphics 实现 A1，看效果再决定要不要出图**。

### 建议暂缓：B2 背景图

理由见上（抢注意力风险）。**先做 A4 的代码渐变**。

## 4. 建议的执行顺序

```
第 1 步（纯代码，无依赖）  A5 修缺陷 → A3 投影/按下态 → A4 背景层次
第 2 步（纯代码，核心）    A1 消除粒子与连锁反馈 → A6 HUD 反馈 → A2 过关庆祝
第 3 步（并行发 Codex）    B1 叠加层重做工单
第 4 步（看情况）          B3 粒子贴图 / B2 背景图
```

**第 1 步与第 2 步不阻塞 Codex** —— 可以立刻开始，工单同时发出去。

---

## 5. 风险与红线

| 风险 | 对策 |
| --- | --- |
| **特效抢注意力** | 核心用户是 50+ 与 8~15 岁。粒子要**短、淡、不遮挡棋子**。`FX_QUALITY` 配置已备好，正好接上 |
| **性能** | 老机器加粒子会掉帧。`FX_SAMPLING`（帧率采样自动降级）已写好但没人用，A1 应当顺手接上 |
| **可读性倒退** | 背景一变复杂，棋子灰度差判据要**重测**（`palette.test.ts` 已能读真实 PNG） |
| **动效变慢** | 现有「节奏」设置（舒缓/明快）必须同样作用于新特效，不能只调棋盘动画 |

> 🔴 **不要因为美化而破坏已固化的判据**：
> 棋子 ≥20 灰度差、触摸目标 ≥52pt、`px()` 换算、首屏 206KB。
> 每一条都是踩过坑才立的。
