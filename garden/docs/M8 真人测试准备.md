## 2. 5 个验收问题 → 怎么观察

框架定的 5 个问题，加上**具体的观察点**与**已知风险**。

### ① 三消爽不爽？

**看**：连锁发生时用户有没有反应（笑、"哦"、身体前倾）。

**已知风险**：
- 特殊棋子的**清除范围是否可预测**。框架 §5 特别提醒过这条：
  各家三消惯例不一致，玩家真正需要的不是"符合行业惯例"，
  而是**能预测这个特殊棋子会清哪里**。
  → **专门观察理解率。若频繁误判，立即改成视觉最直觉的方案，不要坚持理论。**
- 叠加层美术难看是否影响"看得懂"（观感问题已知，但**看不懂**是另一回事）

### ② 旺财烦不烦？

**看**：用户会不会主动提到它？是"这狗真可爱"还是"它一直在动有点吵"？

**已知风险**：
- Idle 微动作是**一直在动**的（摇尾 900ms 周期、呼吸 2600ms）。
  设计假设是"活泼"，但也可能是"晃眼"。
- Hint 在发呆 5s 后让目标棋子**轻微呼吸**。
  设计上刻意不弹窗、不画箭头（"提示，不催促"），
  但对 50+ 用户可能**太隐晦以至于没注意到**。
  → 观察：发呆超过 5 秒的用户，有没有真的顺着提示走？

### ③ 50+ 用户不解释会不会玩？

**🔴 这是最重要的一个问题。** 不要提前教学，把手机递过去看他自己怎么办。

**看**：
- 第一次交换是"拖"还是"点两下"？（两种都支持）
- 看不看得懂 HUD 的"剩余步数"和目标图标？
- 通关后知不知道要点"下一关"？
- **会不会自己找到花园？**

**已知风险**：
- **没有任何新手引导**。Stage 0 刻意没做，就是要测"不解释会不会玩"。
- 目标区用的是**棋子贴图**而不是文字（"收集 12 个黄色"要求玩家把
  "黄色"翻译成"香蕉"，直接画香蕉就不用翻译）—— 这个设计是否成立需要验证。

### ④ 棋子够不够大？

**已做的**：8×8 → **7×7**，棋子边长 +14.3%（iPhone SE 42.9 → 49.0pt），
棋盘占屏宽 91.5%。

**看**：会不会眯眼？会不会点错相邻格子？

**已知风险**：六色的**明度差**理论上达标（最小 22.7 ≥ 20），
但真实环境（昏暗、老花、屏幕色偏）是另一回事。
→ 观察有没有把**梨看成蓝莓**、**葡萄看成苹果**（这两对明度差最小）。
若出现，是重出棋子的信号。

### ⑤ 院门建设是否让玩家愿意继续下一关？

**这是留存的核心假设。** 结算页刻意显示"院门还差 N 颗星"，
就是要卡在"还要不要再玩一关"的决策点上。

**看**：
- 看到"还差 1 颗星"时，会不会**主动**点下一关？
- 建设完院门有没有情绪反应？
- 会不会为了修院门而多玩几关？

**已知风险**：3 关才建一阶段，**可能太慢**（要 9 关才建完院门）。
若用户在第 5~6 关就流失，说明反馈周期太长。

## 3. 建议的测试方法

| 项 | 建议 |
| --- | --- |
| 人数 | 50+ 与 8~15 岁各 2~3 人 |
| 时长 | 每人 15~20 分钟，**不打断** |
| 设备 | **用他们自己的手机**（我们的测试机不代表真实环境） |
| 引导 | **零引导**。只说"你玩玩看" |
| 记录 | 卡住的地方、说出来的话、皱眉的瞬间 |

⚠️ **不要在旁边解释**。用户一旦被教会，问题 ③ 就再也测不出来了。
想问的话等他玩完再问。

⚠️ **iPhone 用户先确认侧面静音开关是响铃档** ——
iOS 的 WebAudio 受它控制，拨到静音时整个网页都没声音，这不是 bug。

## 5. 测试前必须实机确认的一项

**iPhone 微信内的音效。**

已改了三处（每次手势重试 `resume`、播静音 buffer、await `resume()`），
浏览器里验证过 suspended → running 的自救路径，
**但没有在真实的 iPhone 微信里验证过**。

→ 开测前请用 iPhone 微信打开一次，确认有声音。
若没有，**先确认侧面静音开关**（那不是 bug）。

## 6. 测完之后

按反馈优先级，手上已经排好的候选改动：

| 若反馈是… | 对应改动 | 成本 |
| --- | --- | --- |
| "棋盘老是自己动" | 已从源头解决；若仍出现，查 `REFILL_MAX_ATTEMPTS` | 小 |
| "看不出这是什么" | 重出对应棋子 | 中（需 Codex） |
| "炸弹/火箭很丑" | 叠加层美术重做（**已挂着**） | 中（需 Codex） |
| "旺财不够生动" | thinking / hint 专属动作（**已挂着**） | 中 |
| "不知道该干什么" | 加新手引导 | 大（Stage 0 刻意没做） |
| "建设太慢了" | 调 `GARDEN_ECONOMY.nodeStageCost` | 极小（一个数字） |

> `candidates/` 里还留着每张素材的 2~3 个落选版本（110 MB）。
> 若测试反馈要换某张棋子，**可以直接切，不用等 Codex 重出**。
> 这也是为什么它留到 M8 之后再清理。
