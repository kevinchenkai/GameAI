# 1. Style Guide V0.1

## 1.1 总体视觉定位

> **高清、明亮、温暖、圆润、轻 3D、自然治愈。**

参考感觉（不是抄，是定调）：现代休闲三消的柔和 3D 渲染质感 —— 圆润的体积感、柔和的次表面散射、温暖的环境光。

**明确避免**（策划案 §21.2）：
- 廉价小游戏质感
- 纯扁平 UI（要有体积，但不要写实）
- 极度低幼（不是给 3 岁看的）
- 复杂写实（不是照片）
- 高密度信息
- 过度刺眼的高饱和

## 1.2 色板

### 主色板（棋子六色）★ V1.1 已修正

**先说为什么改。** V1 用「色相环六等分」定色板，Codex 审核指出这不等于灰度安全。我实测了原色板的相对亮度（ITU-R BT.709）：

| 原色板 | 灰度值 | 问题 |
|---|---|---|
| orange `#FF9A3C` vs blue `#4FB4F0` | 168.7 vs 162.9 | **Δ=5.8 —— 灰度下几乎相同** |
| orange vs green `#5FD068` | 168.7 vs 176.5 | **Δ=7.8 —— 冲突** |
| green vs blue | 176.5 vs 162.9 | **Δ=13.6 —— 冲突** |
| red `#FF5A5A` vs purple `#A97BE0` | 125.1 vs 140.1 | **Δ=15.0 —— 冲突** |

**6 色里有 4 对冲突。** 原色板通不过我们自己定的灰度硬验收。

**修正后色板**（已验证：两两灰度差最小 25.7，形成清晰阶梯）：

| 语义 | 主色 | 灰度值 | 高光 | 阴影 |
|---|---|---|---|---|
| `yellow` | `#FFDE5C` | **219.6** | `#FFEC9B` | `#D9B12E` |
| `green` | `#7FD957` | **188.5** | `#A8E88A` | `#4E9E33` |
| `blue` | `#5FB0E8` | **162.8** | `#9BCFF2` | `#3579AD` |
| `orange` | `#E0701F` | **130.0** | `#F0A163` | `#A34D11` |
| `purple` | `#7B4FB0` | **95.4** | `#A87FD4` | `#523175` |
| `red` | `#B82533` | **69.3** | `#DB5C67` | `#7D1622` |

**灰度阶梯**（这就是 50+ 与色觉障碍用户的保障）：

```
最亮 ████████████████████ yellow  219.6
     ██████████████████   green   188.5   Δ31.1
     ███████████████      blue    162.8   Δ25.7
     ████████████         orange  130.0   Δ32.8
     █████████            purple   95.4   Δ34.6
最暗 ██████               red      69.3   Δ26.1
```

**这次修正的两个代价，请知悉**：

1. **red 变深**（莓红而非亮红）、**orange 变深**（南瓜橙而非亮橙）。整体仍在温暖治愈范围内，但比 V1 稍沉稳
2. **blue 变亮**（天蓝而非中蓝）

> 如果实际画出来觉得 red 太暗压抑，**可以在保持灰度值 ≈69 的前提下调色相**（偏莓红/偏砖红都可以），但**不要提亮**——提亮就会撞 purple。灰度值是约束，色相是自由度。

## 1.3 光照（**统一，不许每张图各自发挥**）

- **主光方向：左上 45°**
- 主光色：暖白 `#FFF4E0`
- 环境光：柔和天光，冷调 `#E8F0FF`，强度低
- 阴影：**柔和、不死黑**，用 `#7A5A3C` 的 25~35% 透明度，不用纯黑
- 高光：右下无高光，只在左上有一个柔和圆形高光点

## 1.4 造型语言

- **圆润优先**：所有转角有明显倒角，无锐利尖角
- **厚实**：棋子有体积感，像可以捏起来的软胶玩具
- **轮廓清晰**：远看能认出形状
- **描边**：棋子**不用硬描边**，靠明暗与色彩分离；UI 元件用 `#8A6A4A` 的 3~4px 柔和描边
- **细节克制**：小尺寸下细节会糊，宁可少不要多

## 1.5 宠物头身比

- **2.2 : 1**（大头，但不是 Q 版 1:1 的极度低幼）
- 眼睛：大而圆，有高光点，**瞳孔占眼睛 60%**
- 表情靠**眉毛 + 嘴 + 耳朵**三处传达，不靠复杂五官

## 1.6 统一 Prompt 后缀 ★ 必须带

**每一张图的 prompt 末尾都要拼上这段**：

```
Soft 3D casual mobile game art, rounded chunky shapes with clear silhouette,
warm cozy lighting from upper-left 45 degrees, soft non-black shadows,
gentle subsurface glow, bright cheerful palette, no harsh saturation,
clean readable at small size, no text, no watermark, no drop shadow baked in,
centered composition, transparent background.
```

**再拼上尺寸与背景要求**（每张图不同，见 §3–§5 各条目）。

# 3. 棋子素材（第 1 批 + 第 2 批）

## 3.1 尺寸规范

| 项 | 值 |
|---|---|
| 输出尺寸 | **256 × 256 px** |
| 实际显示 | 约 38~43 pt（@3x ≈ 129px），256 给足余量 |
| 背景 | **透明 PNG** |
| 内容占比 | 主体占画布 **85%**，四周留 7.5% 空隙 |
| 底部对齐 | 主体视觉中心在画布正中 |

> **为什么 256**：显示最大约 43pt，@3x = 129px。256 提供 2x 余量，支持后续大屏与特写动画放大，同时单张 PNG 不会太重。

## 3.2 六个普通棋子（第 1 批）★ 最高优先级

**共同要求**：
- 同一材质语言：略带光泽的软胶/糖果质感
- 同一光照：左上 45°
- 同一体积感：厚实圆润
- **形状必须显著不同**（不能都是圆的）

| # | 文件名 | 主色 | 灰度 | 造型 | 形状关键词 |
|---|---|---|---|---|---|
| 1 | `piece-yellow.png` | `#FFDE5C` | 219.6 | **香蕉** | **弯月形** ← 与圆形强烈区分 |
| 2 | `piece-green.png` | `#7FD957` | 188.5 | **梨** | **葫芦形**（上窄下宽） |
| 3 | `piece-blue.png` | `#5FB0E8` | 162.8 | **蓝莓** | 小球 + 顶部星形花萼 |
| 4 | `piece-orange.png` | `#E0701F` | 130.0 | **橘子** | 圆形 + 表面颗粒感 + 顶部蒂 |
| 5 | `piece-purple.png` | `#7B4FB0` | 95.4 | **葡萄串** | **多球聚合**（三角轮廓） |
| 6 | `piece-red.png` | `#B82533` | 69.3 | **苹果** | 圆形 + 顶部凹陷 + 小叶子 |

> **三层编码**（Codex §10.1「Shape First, Color Second」）：
>
> 1. **Silhouette（轮廓）** —— 弯月 / 葫芦 / 带星萼 / 圆带纹理 / 聚合 / 圆带叶，六个各不相同
> 2. **Color（色相）** —— 六色分明
> 3. **Internal Texture（内部纹理）** —— 橘子有颗粒、葡萄有分球线、蓝莓有花萼
>
> 加上 §1.2 的灰度阶梯，任意**单独一层失效**（色觉障碍、小尺寸、灰度）都还有另外两层兜底。

> **形状比颜色更重要**。如果某个造型在 40px 下轮廓不清晰，**优先改造型，而不是改颜色**——颜色已经被灰度约束锁死了，造型才是自由度。

### Prompt 模板（以苹果为例）★ 色值已按 V1.1 更新

```
A single glossy deep berry-red apple game piece, chunky rounded 3D shape,
one small green leaf on top, smooth candy-like surface with a soft highlight
on the upper left, rich deep red #B82533 with lighter #DB5C67 highlights
and #7D1622 shading, simple and iconic, no stem details,
filling 85% of a square frame,
[统一后缀]
Output 256x256 px, transparent background, PNG.
```

其余五个照此替换造型与色值（**用 §1.2 修正后的色值，不要用 V1 的旧值**）。**统一后缀一字不改。**

> ⚠️ **苹果偏深是刻意的**，不是错误。它需要坐在灰度阶梯的最底端，与 purple 拉开距离。若觉得太暗，见 §1.2 末尾的调整余地说明。

## 3.3 特殊棋子（第 3 批；彩虹球推迟到第 4 批）

**设计原则**：特殊棋子 = **普通棋子 + 明显附加特征**。玩家必须一眼看出"这个不一样"，但仍能认出是什么颜色（因为彩虹球以外的特殊棋子仍参与同色匹配）。

| 文件名 | 尺寸 | 内容 |
|---|---|---|
| `special-rocket-h-{color}.png` | 256² | 该色棋子 + **横向箭头光带**贯穿 |
| `special-rocket-v-{color}.png` | 256² | 该色棋子 + **纵向箭头光带**贯穿 |
| `special-bomb-{color}.png` | 256² | 该色棋子 + **发光圆环 + 引信** |
| `special-rainbow.png` | 256² | **彩虹球**：多色渐变球体，柔和流光，无固定色 |

> **`{color}` 需要 6 套吗？** —— **不需要**。为省资产量，火箭与炸弹做成**一套通用叠加层**：
> - `overlay-rocket-h.png`（256²，半透明箭头光带）
> - `overlay-rocket-v.png`
> - `overlay-bomb.png`
>
> 代码在普通棋子上叠加这一层即可。**资产量从 18 张降到 3 张**，且颜色永远匹配。
>
> 彩虹球是唯一的独立素材（因为它本来就无色）。

**彩虹球 prompt**：

```
A magical rainbow sphere game piece, smooth glossy orb with soft flowing
iridescent gradient across pink, yellow, green, blue and purple, gentle inner glow,
premium special item feel, chunky rounded 3D, no text or symbols,
filling 85% of a square frame,
[统一后缀]
Output 256x256 px, transparent background, PNG.
```

# 4. 宠物素材：旺财（第 1 批 + 第 3 批）

## 4.1 角色设定 ✅ 已确认

| 项 | 内容 |
|---|---|
| **名字** | **旺财** |
| **性格** | **活泼、惹人喜爱** |
| **口头禅** | **「快来玩呀！」** |
| 物种 | 小狗 |

### 这个设定对美术的具体要求

「活泼」是本次形象设计的**第一关键词**，它应当直接体现为可见的造型与姿态特征：

- **体态偏动，不偏静**：即使是 Idle 也要有"随时准备蹦起来"的感觉，重心略微前倾，而不是四平八稳地坐着
- **尾巴是第一表情器官**：尾巴要**粗、短、上翘**，容易做出大幅摆动。旺财的情绪 50% 靠尾巴传达
- **耳朵有弹性**：软垂耳，但不要长得盖住脸——耳朵要能随动作甩起来
- **眼睛圆亮**：大而圆，高光点明显，眼神是"看着你"而不是放空
- **嘴角上扬**：默认状态就是微笑，不做面无表情的中性脸

### 「惹人喜爱」的分寸

- 可爱，但**不谄媚、不油腻**
- **不做低幼化处理**（不要奶嘴、不要过度圆滚到失去狗的特征）
- 目标是让 50+ 用户觉得"这狗真乖"，同时让 8~15 岁觉得"这狗真好玩"——**憨态可掬 > 精致漂亮**

### 名字对造型的暗示

「旺财」是非常典型的中式家犬名，带有亲切、接地气、讨喜的意味。造型建议：

- **中华田园犬的气质**（不是贵宾、柴犬、柯基等有强烈品种特征的犬种）
- 毛色建议 **奶黄 / 浅棕**，可在耳朵、尾巴尖做深色点缀
- **不加项圈铃铛等配饰**——保持朴素，让角色靠表情和动作立住

> **口头禅「快来玩呀！」的用法**（供后续文案与动画参考）：这句话是旺财的**招呼语**，用在进入游戏时和长时间未操作时，语气是邀请而非催促。它与策划案 §7.5「提示，不催促」一致——旺财是在叫你一起玩，不是在催你快点。

## 4.2 ★ 第 0 批：Master Reference 先行（Codex 必改 1）

**V1 的做法是错的。** V1 说"保持 Prompt 前半段一致，就能保证是同一只旺财"——Codex 指出这不够稳，我同意。**即便 prompt 一字不差，独立 text-to-image 每次生成仍会漂移**：耳朵长度、眼距、毛色深浅、头型、尾巴粗细、身材比例，都会变。九张图放一起就是九只狗。

**正确流程**：

```
Step 1  生成 pet-wangcai-master
        ↓
Step 2  人工确认「这就是旺财」  ← ★ 卡点，不过不许往下
        ↓
Step 3  所有状态与 Puppet 分层，全部基于 Master 编辑/变体
        ★ 而不是重新从纯 prompt 生成
```

### Master Reference 规格

| 项 | 值 |
|---|---|
| 文件名 | `pet-wangcai-master.png` |
| 尺寸 | **1024 × 1024 px**（比状态图大一倍，留足编辑余量） |
| 背景 | 透明 |
| 内容 | 全身、标准站姿、3/4 侧、中性微笑 |
| 用途 | **不进游戏**，只作角色基准 |

Master 需要一次性锁死这些特征，后续全部沿用：

- 标准比例（头身比 2.2:1）
- 标准毛色（奶黄 / 浅棕 + 耳尖尾尖深色点缀）
- 标准耳朵（软垂耳，不盖脸）
- 标准尾巴（粗、短、上翘）
- 标准眼睛（大圆、高光位置、瞳孔占比 60%）

## 4.3 ★ Puppet 分层结构（Codex 必改 2）

**这是本次工单最重要的结构性修改。**

框架设计要求旺财在 Idle 层持续微动（尾巴摆、眨眼、耳朵抖、呼吸、偶尔看向玩家）——**单张完整 PNG 做不到这些局部动画**。

Stage 0 **不需要 Spine / DragonBones**，用 **Phaser Container + 分层 PNG** 即可。

### Stage 0 最小分层（5 张）

```
assets/pet/wangcai/
├── body.png          躯干 + 四肢 + 头（不含耳朵眼睛尾巴）
├── tail.png          ★ 尾巴（独立，锚点在根部）
├── ears.png          ★ 双耳（独立，锚点在头顶）
├── eyes-open.png     睁眼
└── eyes-blink.png    闭眼
```

### 每层的规格

| 文件 | 尺寸 | 锚点要求 |
|---|---|---|
| `body.png` | 512×512 | 完整画布，其余层与之对齐 |
| `tail.png` | 256×256 | **旋转锚点在尾巴根部**（贴近躯干那端） |
| `ears.png` | 256×256 | **旋转锚点在耳朵根部**（头顶连接处） |
| `eyes-open.png` | 256×128 | 与 body 眼睛位置精确对齐 |
| `eyes-blink.png` | 256×128 | 同上，闭眼版（一条弧线即可） |

|---|---|---|

- [ ] 明度呈阶梯分布，无两个挤在同一档

> ⚠️ **不要因为色板已按灰度算过就跳过此测试。** §1.2 保证的是**色块**的灰度差；实际图有高光、阴影、纹理，会把有效明度**拉近**。算过 ≠ 画出来没问题。
