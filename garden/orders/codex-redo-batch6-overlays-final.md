## 0. 一句话

redo5 **数字全达标，但更难看了** ——
你把明暗跨度从 230 压到 50，是靠**把亮芯砍掉**，不是靠**柔化过渡**。
这一版要求：**跨度照样收窄，但金色高光必须留住**。

## 1. redo5 到底错在哪（实测数据）

### 1.1 亮芯被砍掉了

| 指标 | 旧版（线上） | redo5 | 要求 |
| --- | ---: | ---: | ---: |
| 芯部亮度 P95 | 221~241 | **135~137** | **≥ 190** |

压跨度有两种做法，你选了错的那种：

- ❌ **整体降亮**（redo5 做的）→ 跨度是下来了，但标记发闷发浑
- ✅ **保留亮芯，柔化中间过渡**（要的）→ 跨度下来，高光还在

> 打个比方：要让照片不刺眼，应该降**对比度**，而不是把**亮度**整体调暗。

### 1.2 和水果撞色了

redo5 标记平均色 **RGB(172, 98, 28)**，橙子是 **RGB(222, 113, 34)** ——
**同一族褐橙色**。

芯色到橙子的 RGB 距离：**旧版 107 → redo5 51**，可分辨度腰斩。
亮度差同时只有 43。**亮度和色相两条路一起堵死**，所以糊成一团。

### 1.3 40px 下火箭丢了方向

手机上标记只有约 40px。redo5 的火箭在这个尺寸下
**成了两根发暗的褐色棍子，箭头尖看不出来**。

⚠️ 这是**功能缺陷不是审美问题**：玩家要靠箭头方向预判清除范围。
M8 真人测试会专门观察理解率。

## 3. 🔴 硬判据（脚本会逐条量，不达标直接退回）

1. **芯部亮度 P95 ≥ 190**（redo5 是 135~137，旧版 221~241）
   —— 这条专门防"整体降亮"。
2. **明暗跨度 P95−P05 ≤ 90**（水果实测 37.7~50.8）
   —— 与 §1 不矛盾：亮芯留住，靠**柔化过渡**把跨度压下来。
3. **六色可见性**：每个颜色都要
   - 亮度差 **Δ ≥ 20**（底线，低于此等于看不见），且
   - **「Δ ≥ 60」或「芯色距 D ≥ 90」至少满足一条**
     —— 亮度或色相**至少赢一样，不许两样都输**。
     ⚠️ redo5 正是在**橙子**上两样都输（Δ=43、D=41）。
4. **覆盖面积**：火箭 ≤ 12%，炸弹 ≤ 25%
5. **深色描边 + 亮色芯的双色结构必须保留**（§5.2）——
   这是同时对付浅色香蕉与深色苹果的唯一办法。柔化 ≠ 去掉。

> 💡 第 3 条为什么不是"色距必须 ≥ 90"：
> 旧版金芯在**香蕉**上色距只有 20，却清清楚楚 —— 因为亮度差有 132，靠亮度赢。
> 一刀切要求色距会把公认合格的旧版一起毙掉。**两条路，占一条即可。**

## 4. 自检：一条命令

```bash
python3 tools/check-overlays.py --dir <你的候选目录> --preview /tmp/overlays.png
```

- 退出码 0 = 全过；非 0 会**逐条列出**哪张图、哪个颜色、差多少、为什么
- `--preview` 直接生成验收图（六色合成 + 40px + 深色底），附在交付里
- 依赖仅 Pillow + numpy

**请务必自己跑到退出码 0 再交付。** redo5 报的"最小灰度差 20.0/20.3/20.5"
恰好卡在阈值线上，说明当时是拿单一指标凑的 —— 这次脚本会从多个角度交叉验证。

⚠️ 脚本对**两个方向**都拦：
对比过硬（风格不达标）**和**整体降亮/撞色（可读性不达标）。
不要为了压跨度去洗淡标记 —— 会在第 1、3 条上被拒。
